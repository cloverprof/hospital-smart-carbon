# 医院数智能碳管理平台

面向医院管理层、后勤能源管理人员、碳核算人员、财务资产人员、内部审核和第三方核查人员的高保真前端演示系统。

## 页面与路由

- `/dashboard`：沿用 GitHub 原版“医碳智擎”领导驾驶舱，保留医院夜景数字孪生、能碳 KPI、能源结构、重点系统与 AI 节能机会。
- `/operations`、`/energy`、`/department`、`/systems`、`/equipment`、`/alarms`、`/ai`、`/projects`、`/quality`：原平台后勤、能源、科室、系统、设备、告警、AI、项目与数据质量模块。
- `/carbon/accounting`：碳核算工作台，包含一键试算、数据完整性校验、批量复核、批次锁定、合规报告、活动数据导入导出、能源结构和扩展排放。
- `/carbon/assets`：碳资产管理，包含年度碳预算、情景模拟、履约策略、任务中心、交易台账和合规分析。
- `/carbon/mrv`：MRV 溯源／合规凭证看板，包含全链路溯源、凭证上传预览、SHA-256、数据质量、异常整改、审核核查和证据包导出。

三项碳管理功能复用原平台的窄侧栏、顶部系统栏和内容标题层级，并通过“碳管理”二级导航连续切换。年度、医院、核算范围、核算模式、主题和当前角色使用同一份持久化全局状态。

## 技术栈

React 19、TypeScript、Vite、React Router、Tailwind CSS、ECharts、Zustand、TanStack Table、dayjs、lucide-react、SheetJS 与 JSZip。业务状态通过 Zustand persist 写入 `localStorage`；文件解析、哈希、下载和 ZIP 打包均在浏览器本地完成。

## 演示假设与口径

1. 当前没有医院生产后端，活动数据、排放因子、任务、资产交易、凭证和异常均为结构化 Mock 数据，不用于正式申报。
2. “总院”在顶部代表医院主体的汇总视图；选择东院区或西院区后，核算明细按院区联动。组织范围选择用于表达当前分析层级。
3. 核算采用“活动数据 × 排放因子”的统一服务。制冷剂和麻醉气体因子记录 GWP；各因子同时记录来源、版本和有效期。修改活动数据后自动重算，估算数据单独标记。
4. 合规 PDF 在纯前端演示环境中以 UTF-8 报告内容 Blob 生成；Excel、CSV 和 MRV ZIP 为真实可解析文件。正式系统应由服务端签章、生成 PDF/A 并配置归档存储。
5. 上传文件小于 3 MB 时以 Data URL 持久化供本地预览；更大文件仅持久化元数据和 SHA-256，避免浏览器存储超限。生产系统应接入对象存储与病毒扫描。
6. 角色权限采用演示规则：管理员可锁定和解锁；审核员、核查员和管理员可推进 MRV 流程；管理员和核算员可维护资产交易。正式系统应由统一身份与权限服务控制。
7. 顶部“页面状态”选择器专用于验收加载、空数据、网络错误、无权限和未登录状态，不属于生产业务导航。
8. 医院碳空间剖析使用现有夜景资产和 2D 热点叠加，不依赖复杂三维引擎。
9. 本次集成以 GitHub 原版视觉框架为主，新增页面只扩展碳管理业务域，不替换领导驾驶舱和既有模块。

## 本地数据重置

碳核算工作台的“恢复数据”会重建核算、资产、任务、凭证、异常和审计日志。也可以在浏览器中删除 `hospital-smart-carbon-platform-v2` 本地存储项恢复初始状态。
