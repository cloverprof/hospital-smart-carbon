# 性能与资产可行性报告

测试日期：2026-08-04。测试机：Apple Silicon Mac（macOS 15.6，Darwin 24.6.0）。
浏览器：内置 Chromium 预览浏览器（Chromium 内核）。

## 1. 3D 资产可行性审计（结论：本次不交付 3D，非浏览器硬限制）

### 资产盘点

| 项目 | 数值 |

| `夜景.max` | 100.2 MB（3ds Max 2020 场景源文件） |

### 转换尝试与结论

- 浏览器无法直接加载 `.max` 与 `.vrmesh`（专有二进制格式），必须先离线转换为 glTF/GLB。
- 转换所需软件（3ds Max、V-Ray for 3ds Max）**均无 macOS 版本**，本测试机上不存在任何已授权、可打开该格式的工具；`.vrmesh` 为 Chaos 专有格式，无可靠的合法开源转换器。
- 因此**未能执行**"删除植被→简化网格→导出 GLB→Draco/Meshopt 压缩→纹理分级"的既定流程。

**定性：这是资产转换工具链缺失，不是浏览器/WebGL 硬限制。** 本报告不主张"3D 不可行"，也未伪造模型转换结果。按主规格 10.2 条，未通过可行性门槛时顶栏不提供可开启的 `3D 环绕` 开关（当前显示为禁用态并在 tooltip 说明原因）。恢复路径见 `IMPLEMENTATION_GAPS.md` 第 1 条。

### 若未来提供 GLB，需满足的运行门槛（尚未测试）

首屏可交互 ≤4 秒；首屏 3D 资源 ≤50 MB、全部渐进资产 ≤100 MB；1920×1080 与 2560×1080 平均 ≥50 FPS、1% low ≥30 FPS；30 分钟无内存持续增长与 context lost；点击名牌 100ms 内反馈。

## 6. 长时运行测试（30 分钟，后勤驾驶舱）

测试对象：后勤驾驶舱（含 5 秒实时刷新、事件流轮播、多个 ECharts 实例）。
采样：每 60 秒记录 JS 堆占用与 DOM 节点数；连续 requestAnimationFrame 帧率采样；监听 error / unhandledrejection / webglcontextlost。

**实测结果（2026-08-04，30 分钟连续运行，脚本 `scripts/soak.mjs`，原始数据 `docs/soak-result.json`）：**

| 指标 | 结果 | 判定 |
|---|---|---|
| 平均帧率 | 60 FPS（1784 次逐秒采样） | 通过（门槛 ≥50） |
| 最低帧率 | 55 FPS | 通过 |
| 1% low | 60 FPS | 通过（门槛 ≥30） |
| JS 堆占用 | 起 9 MB → 终 15 MB，峰值 15 MB | 通过，无持续增长 |
| DOM 节点数 | 起 273 → 终 301（随事件流轮播小幅波动） | 通过，无累积泄漏 |
| WebGL context lost | 0 次 | 通过 |
| 未捕获错误 / console error | 0 条 | 通过 |

测试期间每 5 分钟切换一次驾驶舱右栏 Tab，模拟真实值守操作。5 秒实时刷新与事件流轮播全程运行。
内存 6 MB 的增长发生在前 3 分钟（图表实例与缓存预热），此后 30 分钟稳定在 12-15 MB 区间无上升趋势。

## 7. 已采取的性能措施

- 场景层、名牌层、数据面板层、顶栏/弹窗层为独立合成层；面板使用 CSS `contain: content`，背景不触发面板重排。
- ECharts 统一走 `EChart` 包装：ResizeObserver 自适应、`visibilitychange` 时暂停动画（恢复不补算）、卸载时 `dispose()` 释放实例。
- 实时数据用固定长度环形轮播（事件流最多 8 条循环），不无限追加。
- 数据引擎带结果缓存（上限 4000 条后清空），确定性输入避免重复计算。
- 定时器统一在 `useEffect` 清理函数中 `clearInterval`；页面隐藏时跳过刷新。
- 提供 `prefers-reduced-motion` 降级（全部动画与过渡缩至 0.01ms）。
- 驾驶舱与重型模块按路由 `lazy` 加载，登录页首包不含图表库与业务模块。
